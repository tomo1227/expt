# AI-DLC v2 workflow migration

## 状態

実施中。Issue [#2](https://github.com/tomo1227/expt/issues/2)。

## 目的と仮説

- 解決したい問題: 独自のIssue→PRフローと承認方式の保守をやめる。
- 検証可能な仮説: 固定した公式Copilot用配布物で、要求整理・人の承認・実装・状態復帰を一つの導線から実行できる。
- 対象範囲: Dev Container、Copilot、関連する指示・テンプレート・検証。
- 今回やらないこと: アプリ導入、他ハーネスの設定、自動起動、自動マージ。

## 成功条件

- [ ] 同じ配布物を再構築・復元できる。
- [ ] VS Codeで実際にフックが動き、承認前に保護された工程へ進まない。
- [ ] 人の承認後に再開でき、新規セッションで状態を復元できる。
- [x] フック未実行・登録欠落を検知し、成功と誤報しない。
- [x] 旧フローの競合指示がなく、APM管理物を保持する。
- [x] `make check` と導入整合性チェックが成功する。

## 実装と検証の計画

1. 公式 `v2.11.4` / commit `61fdb122428d86b56b7e8d598787095f2c97d3e1` を使用する。
2. 固定インストーラーのSHA-256を検証し、native CLIでCopilot構成を生成する。
3. `make aidlc-setup` で再展開可能にし、実行用 `.aidlc/` とローカルVS Code設定はGitに含めない。
4. プロジェクト固有ルールと旧コマンドを移行し、構成チェックを追加する。
5. CLI診断と対話検証を分け、未検証を残したまま成功・採用としない。
