# APM CLI のコンテナ導入

## 状態

採用

## 目的と仮説

- 目的: Dev Container で Agent Package Manager を利用できるようにする。
- 仮説: 公式 Unix インストーラーで共有パスへ配置すれば、非 root の `vscode` ユーザーから利用できる。
- 対象範囲: Dockerfile と利用手順。CLI バージョンは `0.35.1` に固定する。
- 今回やらないこと: `apm init`、外部パッケージ追加、既存指示の生成・上書き、CI のコンテナ起動検証。

## 成功条件

- [x] Dev Container がビルドできる。
- [x] `vscode` ユーザーで `apm --version` が成功する。
- [x] コンテナ内の `make check` が成功する。

## 実装と検証の計画

1. 公式インストーラーを `curl -fsSL` で取得し、指定バージョンを `/usr/local` 配下へ導入する。
2. ビルド後に非 root ユーザーで起動して、root 専用の導入になっていないか確認する。
3. コンテナ内で既存の共通チェックを実行する。

## 結果

- `devcontainer build --workspace-folder . --image-name expt-apm-check`: 成功。
- 初回は root の起動確認のみ成功し、`vscode` では PyInstaller の読み込みエラーになった。
- 原因: インストーラーが `/usr/local/lib/apm` を root 専用の `0700` で作成した。
- 修正: CLI バンドルへ `chmod -R a+rX` を適用し、一般ユーザーの読み取り・実行を許可した。書き込みは許可しない。
- `docker run --rm --user vscode expt-apm-check apm --version`: `0.35.1` を確認。
- リポジトリを読み取り専用でマウントしたコンテナで `make check`: 成功。
- 未検証事項: 他の CPU アーキテクチャ、外部パッケージの導入と既存指示との併用。
- 再現性の制約: CLI は固定しているが、公式インストーラーの URL は可変。
- 判断: CLI 導入のみを採用。利用者は Dev Container を再ビルドして利用する。
